## Decisions
- **R15/R16 rules are parameters** (`R15Rules`/`R16Rules`: allowlist, native coin, Solana limits and `sameAddress`/`parseAtomic`), so core has no runtime import and not even a type import of `@hako/*` (the plugin typechecks it on a clean clone without the root install). `r15RulesFor`/`r16RulesFor` in `./server` show the assembly; the plugin (L1) builds the same object from its relative imports of config/networks/money.
- **R15 binds more than the plan's list, all fail closed**: to-chain and to-token too, the EVM tx's `chainId` and `from`, and `value` (an ERC-20 move must send 0 native; a native move exactly the amount). A route that charges a native fee on an ERC-20 transfer is therefore refused — the route race should run `bindQuote` at quote time to drop such rows. Solana also refuses non-canonical base64 and versions other than legacy/v0.
- **`NormalizedQuote` satisfies `DraftQuote`** (checked at compile time in `@hako/paybox/src/contract-checks.ts`); its `expiresAt` = `quotedAt + QUOTE_CACHE_TTL_S`; `approvalAddress` is null for native coins and Solana.
- **drafts table = versions table**: the PK `(draft_id, version)` is the unique row; `claimDraftExecution` sets `executed_at` once (the "insert the unique row first" step), `recordDraftRequest` sets the request id once. DraftStore maps 1:1: insertDraft→`insertDraft`, getDraft→`getLatestDraft`, getVersion→`getDraftVersion`, appendVersion→`appendDraftVersion`, setState→`setDraftState`, claimExecution→`claimDraftExecution`, recordRequest→`recordDraftRequest`, getExecution→`getDraftExecution` (rows carry `Date`s; the adapter turns them into ISO strings).
- **One active PayBox link per user** (partial unique index); revoked links stay as history. A changed `PAYBOX_OAUTH_REDIRECT_URL` revokes the old link and registers a new client (PayBox matches redirects exactly). `sub` is an attribute set once; a different `sub` on the same client throws `PayboxSubjectMismatchError` (L4 picks the UX; SP10 still pending).
- **Better Auth Phase 1 enables no sign-in method** (only what the brief lists: sessions, `jwt()`, `nextCookies()`); how a Hako user is created (e.g. the anonymous plugin + Connect PayBox) is L4/L5's call, with a new migration from `migration:generate` if it adds columns.
- **`@hako/db/migrate` is its own entry**: Turbopack resolves `new URL('../migrations/', import.meta.url)` as an asset, so the runner stays out of the root and `/node`.
- **`@hako/defi/server` has no `server-only` guard**: gateway and CLI only (ESLint already bans it in client code). Next code doesn't import it (the web reaches LI.FI through the gateway).
- **Dependencies outside the catalog**: `@types/pg` 8.23.1 (the types of the §3 `pg` pin, published 2026-08-17) in db; `tsx` 4.23.15 (the version the lockfile already had for the gateway) as defi's test runner — `@hako/money`'s parameter properties stop Node's own type stripping. `erasableSyntaxOnly` is on in db and auth so their Node-run scripts stay strippable.
