## Routes (all paths from `GATEWAY_ENDPOINTS`)
| Route | What |
|---|---|
| `POST /v1/batch` | zod `batchRequestSchema`; every id must be in the live catalog (404 otherwise); every input checked with hako-api `/v1/validate/<id>` in parallel (422 with per-call details; 502 if the api can't answer); sum of catalog `price.atomic` frozen; stored in Redis `hako:gw:batch:<id>` for `BATCH_TTL_S`; answers `batchResponseSchema` with `paidUrl`. |
| `GET /v2/batch/:batchId` | pre-check: stored result → 200 (never another 402); unknown/expired → 404 (never a 402); claimed → 409 `batch_settling`. Then x402 `exact` with `DynamicPrice` = the stored frozen sum, payTo = Hako; the handler runs every call in parallel and answers 502 `batch_incomplete` (no settlement) unless every call answered 200 and billable. `onBeforeSettle` `SET NX hako:gw:batch:<id>:claim` (TTL = batch TTL, so a settled batch can never be claimed again), `onAfterSettle` stores the delivered body as the result, `onSettleFailure` drops the claim. |
| `POST /v1/invoices` | 20/min per IP (`X-Real-Ip`, else last `X-Forwarded-For` hop); `invoiceCreateRequestSchema`; amount 0.01–1,000 USDC; note trimmed, no control/format chars; optional Hako bearer → `createdBy` (invalid bearer → 401); `@hako/db createInvoice` (chain = rail network, asset = its USDC); answers `invoiceDataSchema`. |
| `GET /v1/invoices/:id` | `invoiceDataSchema`, 404 unknown. `settling` reads as `open`. |
| `GET /v2/invoice/:id` | unknown → 404; paid, settling, or Redis claim present → 200 with the invoice (never another 402); open → x402 with `DynamicPayTo` = invoice payee and `DynamicPrice` = its amount (memoised per id: immutable). `onBeforeSettle`: `SET NX hako:gw:invoice:<id>:settling` then `claimInvoice` (open → settling), else abort; `onAfterSettle`: `markInvoicePaid` with tx + payer; `onSettleFailure`: `releaseInvoice` + drop the key. The handler's body is the invoice as it stands once paid (status paid, payer from the signed authorization; tx hash in `PAYMENT-RESPONSE` and on `GET /v1/invoices/:id`). |
| receipts on every settlement | `recordSettlement(pool)` on every resource server (run, batch, invoice): `x402_settlement`, `confirmed`, surface `gateway`, chain/asset/amount/payer/payTo/tx from the settle result, plus `toolId` / `batchId` / `invoiceId` read back from the path. Idempotent per (kind, chain, tx). No DB → logged `receipt_not_recorded`. |
| `GET /v1/receipts` | Hako JWT required (401 `auth_required` / `invalid_session`); `receiptsQuerySchema` filters (kind = card kind, status `reverted` ↔ db `failed`, chain, surface, draftId); keyset cursor (base64url `{createdAt, id}`); `receiptsPageSchema`. |
| `GET /v1/receipts/shared` | public `is_public` rows, newest first (no filters, per contract). |
| `GET /v1/receipts/:id` | the receipt if shared, or to its owner (bearer); otherwise 404. |
| `POST /v1/receipts` | `hako_receipt`: Hako JWT; reads the tx through hako-api's chain tx connector (`READ_ALIAS_CONNECTORS.chainTx`, i.e. `chain-evm/tx` / `chain-solana/tx` — **L2 builds them; until then this answers 502 `chain_unavailable`**); records a `paybox_transfer` receipt for the caller (sender's token transfer, else native value), refuses one another account recorded (409), moves a pending one on. |
| `GET /v1/logo?src=` | https, allowlisted hosts only (`LOGO_HOSTS`, measured from LI.FI tokens/tools/chains), redirects followed only to allowlisted hosts (≤ 3), image types only, ≤ 512 KiB read as a stream; cached in Redis 24 h and `Cache-Control: public, max-age=86400, immutable`; sandboxing CSP + nosniff on every image. |
| `GET /v1/files/:id` | id `[A-Za-z0-9_-]{1,128}`; forwards hako-api `GET /v1/files/<id>` bytes (content-type, length, etag…), 404 passthrough, 502 otherwise. **hako-api has no `/v1/files` yet (L2, ElevenLabs).** |

Runtime: Redis from `REDIS_URL` (in-memory store only when `NODE_ENV` ≠ production; production without it → batch/invoice routes 503); Postgres from `DATABASE_URL` (invoices and receipt reads 503 without it). Hako JWTs verified with `jose` against `${HAKO_AUTH_ISSUER ?? https://usehako.xyz/api/auth}/jwks` (issuer checked, `sub` = user id). The 402's `resource.url` uses `HAKO_PUBLIC_URL` (a `x402HTTPResourceServer` subclass wraps the adapter's `getUrl`).

## Review fixes (branch `fix-l1-gw-x402`)
1. **Logo proxy could fill the shared Redis** (`routes/logo.ts`). Upstream fetches (cache misses) are now limited per
   `clientIp(c)` with `kv.hit` — `LOGO_FETCHES_PER_WINDOW` = 120 per `LOGO_RATE_WINDOW_S` = 60 s, 429 `rate_limited`
   through `refuse` (cached logos don't count). Only logos ≤ `LOGO_CACHE_MAX_BYTES` (64 KiB) go into Redis; a bigger one
   is served with `public, max-age=86400, immutable` and left to browsers. The cache key drops the URL fragment.
   Verified locally: miss 605 ms → hit 2 ms → `#x` variant 1 ms (same entry); a 124 KiB PNG served 200 twice, Redis logo
   keys unchanged (3 → 3); counter at 120 → next miss 429, a cached logo still 200, another client's miss 200.
2. **Duplicate HTTP constants**: `HTTP_UNAUTHORIZED` / `HTTP_PAYMENT_REQUIRED` removed from `x402.config.ts`; `http.ts`,
   `invoice.ts`, `receipts.ts` and `batch.test.ts` import them from `@hako/cards/contract`.
3. **Duplicate surface enum**: `cards.ts` uses `activitySurfaceSchema.safeParse(row.surface).data ?? null`.
4. **`POST /v1/receipts` now binds the tx to the caller's send draft** (`x402/onchain-receipt.ts`). `draft` is required
   (422 `draft_required`); the draft must be the caller's, or unclaimed and then claimed for them
   (`claimDraftExecution`, request kind `transfer`, only after the tx matched); it must be a `send` (422
   `not_a_send_draft`) on the same chain; the tx must come from the draft's `from` and move exactly its token and
   amount to its `to` (ERC-20/SPL transfer log, or native `to` + `value`), else 422 `tx_mismatch`. A token send still
   pending without logs → 409 `tx_pending` (retryable); a reverted token call from the sender to the token contract is
   recorded as failed with the draft's terms. The receipt records the draft's sender as payer. Unit test
   `onchain-receipt.test.ts` (`sentAsDrafted`: match, other sender/recipient/amount/token refused, native, pending,
   reverted). **Note for L5/agent:** `hako_receipt` sends `draft` only when the model passes it; without one the
   gateway now answers 422 `draft_required`.
5. **Invoice stuck in `settling`** (`invoice.ts`). `recovered(row)` runs on `GET /v1/invoices/:id` and in the
   `/v2/invoice/:id` pre-check: a `settling` row with no Redis claim is marked paid from its `x402_settlement` receipt
   (new `@hako/db` helper `getReceiptByInvoice`) or released to `open`. `settled()` retries `markInvoicePaid` once.
   Verified locally: settling + no claim + no receipt → open, then 402; settling + no claim + receipt → 200 paid with the
   receipt's tx and payer (DB row paid); settling + live claim → untouched (200, still settling).
6. **Invoice price decimals**: the pre-check answers 404 `mainnet_disabled` without a rail, 503 without the rail's USDC,
   and 503 for an open invoice whose chain or asset isn't the rail's; `price` uses `usdc.decimals` with no fallback.
   Verified: an open row moved to `eip155:84532` → 503, no challenge; a 0.01 USDC invoice → 402 amount 10000.
7. **Receipt write off the paid response path** (`x402/settlement.ts`): `recordReceipt` is started with
   `void …then(log).catch(log)` and the hook returns at once (idempotent on (kind, chain, tx)). `/v2/run` still 402.
8. **Unreachable issuer ≠ invalid session** (`x402/session.ts`): only jose token errors (JWTExpired,
   JWTClaimValidationFailed, JWSSignatureVerificationFailed, JWSInvalid, JWTInvalid, JWKSNoMatchingKey,
   JOSEAlgNotAllowed, JOSENotSupported) are `invalid`; anything else (JWKSTimeout, network) is `unavailable`, logged
   `session_check_unavailable`, and `POST /v1/invoices`, `GET /v1/receipts`, `POST /v1/receipts` answer 503
   `session_unavailable` (retryable). `GET /v1/receipts/:id` keeps 404 for a private receipt (no existence leak).
   Test added in `session.test.ts`; verified locally with the unresolvable default issuer: bearer → 503, garbage → 401.
   **Deploy:** set `HAKO_AUTH_ISSUER` on hako-gateway to the live web host's `/api/auth` (main now defaults to
   `https://usehako.site/api/auth` after the domain move) — not changed from this lane.
9. **package.json / pnpm-lock.yaml outside owned paths**: coordinator decision — accepted as dependency-only; resolve at
   merge by taking the union of dependencies and re-running `pnpm install`. Nothing else changed.

## Open (for the coordinator)
- `refuse()` in `routes/x402/http.ts` writes the same envelope as `src/errors.ts` `jsonError` for 401/409/422/429, which `ErrorStatus` doesn't allow; fold by widening `ErrorStatus` at merge and delete `refuse`.
- `session.ts` verifies Hako JWTs for these routes; L5's `src/oauth` (MCP auth gate) should reuse it (or replace it) rather than add a second verifier.
- x402 receipts carry no Hako user (plugin and `use_service` payments have no session): `GET /v1/receipts` lists only rows with the caller's `user_id`. Activity's address match (`listReceiptsForAddresses` by the user's PayBox wallets) needs the wallets, which the gateway doesn't have; the web/agent side can pass them if the contract grows an `addresses` filter.
- Deploy: set `REDIS_URL` and `DATABASE_URL` on hako-gateway (Coolify) to `hako-redis` / `hako-postgres`, and run `pnpm --filter @hako/db migrate` against hako-postgres once, or batches and invoices answer 503 in production.
- An invoice left `settling` is now finished from its x402 receipt or released once its Redis claim expires (fix 5).
  Residual: if Postgres was down for both the receipt write and the paid mark of a settlement that did land, the row
  is released and could be paid a second time; only an on-chain check of the payee's USDC transfer would close that.
- `extensions.bazaar` on the paid routes is not added (would pull `@x402/extensions`, currently external in the bundle).
