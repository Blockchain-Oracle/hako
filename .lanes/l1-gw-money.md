# L1 gateway money routes (lane `l1-gw-money`) — notes

Branch `lane/l1-gw-money` (cut from `origin/main` 4f3d2e6). Plan §1 B13 + the read aliases, typed by the endpoint
table in `packages/cards/src/contract/gateway/endpoints.ts` (every request and response is that table's zod schema;
paths are read from `GATEWAY_ENDPOINTS`, so they cannot drift).

## What exists now
Registered with one call in `services/gateway/src/routes/index.ts` (`registerMoneyRoutes(app, config)` + its import).

| Route | File | What it does |
|---|---|---|
| `POST /v1/quote` | `routes/money.ts` | One LI.FI `/quote` (pinned `allowBridges`/`allowExchanges=[tool]` when `tool` is given), cached `QUOTE_CACHE_TTL_S` (15 s) by request hash, answered as the contract's `route` (`routeDataSchema.parse`, so drift fails in the gateway). Only a quote that can become ONE PayBox proposal is returned: R15 is run on the quote's own tool and floor (EVM: one call to LI.FI's allowlist with no stray native value; Solana: ≤ 1,232 bytes, one signer = sender). If LI.FI's own pick fails that and no tool was pinned, the contenders are raced inside one route budget (4 s) and the best proposable one is returned; otherwise 404 `no_route`. With `draft`, the quote carries its rehearsal (approve + transfer on EVM). |
| `POST /v1/routes` | `routes/money.ts`, `money/race.ts` | The route race as NDJSON (`application/x-ndjson`, `cache-control: no-store`): one snapshot at start (all rows `asking`, names/logos from LI.FI `/tools`, cached 1 h), one per settled row, the last `done: true`. One `/quote` per contender in parallel, `ROUTE_RACE_ROUTE_TIMEOUT_MS` each, `ROUTE_RACE_TOTAL_TIMEOUT_MS` in all; rows that fail the single-transaction check are `failed` with the reason; `winner` = most received among answered rows (the leader while running). Closing the stream aborts every quote. Contenders when the caller names none: `RACE_BRIDGES` across chains, `RACE_EVM_EXCHANGES` / `RACE_SOLANA_EXCHANGES` on one chain (`money/money.config.ts`). |
| `POST /v1/bridge` | `money/proposals.ts` | R17 (`isExecutableCaip2`: Base, Solana) → fresh quote pinned to `tool` (never cached) → R16 on EVM (`planApproveSequence` with the on-chain `allowance` read through viem on the public RPCs and LI.FI's `approvalReset`): a short allowance answers ONLY `{step: "approve"}` with the exact-amount calldata → else R15 `bindQuote` against the reviewed route + `minReceivedAtomic`: `{step: "transfer", route, tx}` (EVM call with LI.FI's `gasLimit`, or the Solana tx with signer and byte size), `{step: "review", route, reason}` on a lower floor, 400 `r15_<reason>` / `r16_<reason>` when refused. |
| `GET /v1/bridge/status` | `routes/money.ts` | `lifiStatus` → the contract's legs (explorer links from `@hako/networks`); LI.FI's 404 for an unknown hash is `status: "not_found"`, not an error. |
| `POST /v1/earn/deposit`, `/v1/earn/withdraw` | `routes/money.ts` → `buildProposal` | LI.FI Composer: deposit = token → vault, withdraw = vault shares → token, same chain, recipient = sender; the same R17 → R16 → R15 sequence (the share approve on withdraw when the quote names a spender). EVM only. |
| `POST /v1/rehearse` | `routes/rehearse.ts` | EVM: viem `simulateCalls` (`eth_simulateV1`) from the user's address on the executable chain's public RPCs (`fallback` transport over `@hako/networks` `rpcUrls`); Solana: `simulateTransaction` (unsigned: `sigVerify: false`, `replaceRecentBlockhash: true`) on Helius, then the public RPCs. Budget `REHEARSAL_TIMEOUT_MS`: over it → `skipped` with "Rehearsal took longer than 1500 ms…" (never cached); an RPC that can't answer → `skipped` with the reason; a non-executable chain → `unsupported` "Not rehearsed on <chain>". Cached per `id:version` + body hash for `REHEARSAL_CACHE_TTL_S` (a different body can't read another's result). |
| `POST /v1/broadcast` | `routes/broadcast.ts`, `money/broadcast-checks.ts` | No key (R8). Decode-and-check (EVM: `parseTransaction` + `recoverTransactionAddress`; chainId, from, to, data, value equal the draft; a LI.FI kind may only call the allowlisted Diamond or be R16's exact approve of the reviewed amount on the reviewed token; Solana: ≤ 1,232 bytes, one slot/one required signer, fee payer = signer, message byte-for-byte, ed25519 signature verified with node:crypto) → EVM nonce == `eth_getTransactionCount(from, 'pending')` (lower + already on chain → `already_known`, else refused stale; higher → refused) → re-simulate at `latest` (`eth_call` with the tx's gas) / Solana `isBlockhashValid` + signed `simulateTransaction` → claim `sent:<chain>:<hash>` (Redis `SET NX`, else memory) → one `eth_sendRawTransaction` / `sendTransaction`; "already known" → `already_known`; a node refusal releases the claim → `refused`. Refusals say "Signed but not sent — no money moved: …", `moneyMoved: "no"`. Sent → `moneyMoved: "unknown"` (on its way, not landed). |
| `POST /v1/chain/{balance,token,tx,block,gas,call,logs,name}`, `/v1/markets`, `/v1/earn/vaults`, `/v1/earn/positions` | `routes/aliases.ts` | Body checked against the table's schema, then `forwardRead` to hako-api `POST /v1/run/<connector>` where the connector comes from the contract's one alias table `READ_ALIAS_CONNECTORS` (`chain-evm/*` / `chain-solana/*` by the chain's family, `hako/markets`, `lifi-earn/{vaults,positions}`). A read a family doesn't have (a block on Solana) → 400 `unsupported_read`. Only those fixed ids are ever forwarded. |

## Decisions
- Paths come from `GATEWAY_ENDPOINTS[key].path` and the alias table from `READ_ALIAS_CONNECTORS`: the contract is the one source of both (the brief's `chain_evm/*` naming is the contract's `chain-evm/*`; catalog ids allow only `[a-z0-9-]`).
- Errors use the gateway's `jsonError` statuses (400/404/502/503); R15/R16 refusals are 400 with `r15_<reason>` / `r16_<reason>` codes rather than 422 (`ErrorStatus` in `errors.ts` has no 422 and that file isn't this lane's).
- `/v1/quote` and the race read through the 15 s cache; `/v1/bridge` and Earn proposals always bind a fresh, uncached quote.
- The raw LI.FI step is kept beside `NormalizedQuote` (`quotes.ts` `freshQuote` = `getQuote(quoteRequest(...))` + `normalizeLifiStep`): the route card's `fees[]`, `fromAmountUsd`/`toAmountUsd` and R16's `approvalReset` exist only there.
- Logo URLs stay LI.FI's: `@hako/identity`'s `LogoImage` proxies them itself (proxying here would double-proxy).
- Solana RPC: Helius first, then `@hako/networks`' public Solana RPCs (Helius' plan answered 429 "max usage reached" today). Without the fallback every Solana rehearsal would be `skipped`.
- Rehearsal EVM coverage follows R17: only executable chains (Base) rehearse; others are `unsupported`.
- `moneyMoved` for `sent`/`already_known` is `unknown`: the transaction is on its way, not landed.

## Open (for the coordinator)
- **W0.6 wiring:** `useStoredExpectations(lookup)` (routes/broadcast.ts) points `/v1/broadcast` at drafts stored in `@hako/db` (the lookup turns a stored draft version into a `broadcastExpectationSchema` value: kind, the bound tx, the reviewed route); until it is wired, only posted drafts (CLI, `hako_broadcast`) can be relayed and a draft-less post is refused. The PayBox wallet-sign poller calls `relaySignedTransaction(chain, signedTx, expectation)` for every `success` — the same check-and-send path. Request-creation fields (one open request per wallet/chain lock, `nonce` from `pending`, `maxFeePerGas = BASE_FEE_MULTIPLIER × base fee + priority`, `gas` = LI.FI `gasLimit`) belong to `executeDraft` in `@hako/paybox`.
- **Receipt tracking** after `sent` (confirmed / reverted, a `receipts` row) needs `@hako/db`; the card can follow `/v1/chain/tx` or `/v1/bridge/status` meanwhile.
- **Bridge status tokens:** `@hako/defi`'s `lifiStatus` drops LI.FI's `sending/receiving.token` and the sent amount, so the legs carry `token: null` (the received amount is there). Adding them to `LifiTransferStatus` lets the route fill them (packages/defi is not this lane's).
- **Helius:** the key's plan is exhausted (429 "max usage reached"); the public-RPC fallback covers it, Helius returns once topped up.
- **Redis:** set `REDIS_URL` on hako-gateway (the money cache, rehearsal cache and the send-once claims use it; memory otherwise, per replica). Batch/invoice routes may want to share `money/runtime.ts`'s store (move it up to `services/gateway/src/` at merge).
- `LIFI_API_KEY` is empty: quotes and the race run keyless (rate-limited); Earn vault/position reads are L2's connectors behind the aliases.
